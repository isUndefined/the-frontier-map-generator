# Самостоятельная генерация The Frontier

Промпт, маска и canvas должны относиться к одному текущему проходу.
В тексте используются только координаты отправляемого canvas. Координаты
тайла и мира находятся в zones.json и модели для генерации не нужны.

## Обновление уже подготовленного job без сброса прогресса

```sh
git switch feature/docker-world-generator
git pull --ff-only origin feature/docker-world-generator
docker compose build generator
docker compose run --rm generator refresh-prompt --job tile_x-2_y+0
```

`refresh-prompt` обновляет только `input/prompt.txt`, сохраняет предыдущую
версию текста и не меняет PNG, маску, принятые проходы или опубликованный тайл.
`rebuild-job` нужен только для начала с нуля, не для повтора неудачного прохода.

## Генерация каждого прохода

1. Открой новый запрос генерации/редактирования изображения, чтобы старые
   вложения не смешивались с новым проходом.
2. Прикрепи текущие `input/generation_canvas.png` и `input/generation_mask.png`.
3. **Вставь в сообщение полный текст `input/prompt.txt` без своих дополнений.**
   Не заменяй его краткой просьбой «продолжи карту». Приложенный TXT можно
   оставить третьим файлом, но точная инструкция должна быть в сообщении.
4. Сохрани исходный PNG результата как `jobs/tile_x-2_y+0/generated.png`.
   Для west/east нужен 1536×1024, для north/south — 1024×1536.
   Не изменяй размер вручную и не сохраняй скриншот вместо исходного PNG.
5. Проверь результат:

```sh
docker compose run --rm generator check-job --job tile_x-2_y+0 --strict
```

Проверка не принимает проход и не меняет прогресс. Она создаёт:

- `draft/generation_check.txt` — краткий результат и следующий шаг;
- `draft/generation_check.json` — измерения, пороги, конкретные причины отказа;
- `draft/pass_preview.png` — собранная часть тайла;
- `draft/locked_context_difference.png` — изменения существующего контекста;
- `draft/locked_context_preview.png` — результат с точно восстановленными
  locked-пикселями, чтобы увидеть реальный стык.

Код возврата команды: 0 — текущий проход принят проверкой, 1 — отклонён.
Сравнение ориентиров только проверяет геометрию: ни один пиксель не сдвигается,
не поворачивается и не масштабируется. Порог остался 2 px. Существующие
overlap-пиксели восстанавливаются точно из исходников при сборке.

## Если проверка отказала

Открой `draft/generation_check.txt`. Для неверного размера сначала проверь,
что скачан исходный PNG. Не пытайся увеличить его вручную.

Для повторной генерации приложи **те же исходные canvas и mask** и вставь
полный текст созданного `draft/retry_prompt.txt`. Не прикладывай неудачный
`generated.png` в качестве референса: это может закрепить неверную геометрию.
Сохрани новый результат поверх `generated.png` и снова выполни `check-job`.

Входные PNG, маска, принятые участки и опубликованная карта при отказе сохраняются.
Ослабление порогов, ручное расширение маски и `--allow-weak-alignment` для этого
цикла не требуются. Генерация остаётся вероятностной: автоматические проверки
не гарантируют красивый или географически связный рельеф. Проверь preview.

## Принятие и следующий проход

Если проверка прошла и изображение устраивает:

```sh
docker compose run --rm generator advance-job --job tile_x-2_y+0 --strict
```

Команда повторяет проверку, сохраняет принятый участок и выдаёт новые canvas,
mask и prompt. Для (-2,0) по умолчанию три прохода. После первого и второго
повтори шаги генерации с новыми файлами. Старый `generated.png` архивируется,
чтобы его нельзя было случайно принять ещё раз.

## Последний проход и публикация

На последнем проходе `check-job` сообщает `tile_complete: true` и следующий
шаг. `advance-job` на последнем проходе ничего не меняет и предлагает finalize.

```sh
docker compose run --rm generator finalize --job tile_x-2_y+0 --draft --strict
```

Проверь `draft/world_preview.png`, `draft/primary_pair_preview.png` и
`draft/quality_report.json`. Итоговый тайл остаётся 1672×941 px.
После визуальной проверки замени опубликованную версию:

```sh
docker compose run --rm generator finalize --job tile_x-2_y+0 --replace --strict
```

Старый тайл и метаданные сохраняются в backups. ZIP не нужен.

## Что было проверено

Программные тесты проверяют точную маску с отверстиями, все четыре направления,
диагонали, сохранение пикселей и прогресса, отказы и rollback. Они не доказывают
художественную связность генерации.

Ручная проверка нового промпта проводится через встроенный image_gen: два PNG
и точный неизменённый текст созданного prompt.txt. В запрос не добавляются
ручные координаты или описания рек. Это проверка конкретных генераций, а не
гарантия одинакового поведения любых интерфейсов или моделей.
