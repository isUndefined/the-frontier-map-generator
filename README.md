## OpenAI Image Edit (native resolution)

Copy `.env.example` to `.env` and supply your own `OPENAI_API_KEY`.
Run `docker compose build generator`, then `docker compose run --rm generator expand --direction west`.
Already prepared `tile_x-2_y+0`? Run `docker compose run --rm generator finalize --job tile_x-2_y+0`.
**No resize/upscale**: minimum padding and exact crop; fixed pixels are restored.
See [DOCKER_WORLD_GENERATOR.md](DOCKER_WORLD_GENERATOR.md) for details.

# Сборка карты из локальных tiles

Каждая зона хранит **только свой tile**, включая полосы перекрытия с соседями.
Накопленная панорама не сохраняется в папках зон. Общая карта создаётся отдельно
в `jobs/_grid`, когда она нужна; после каждого нового tile запускать сборку необязательно.

## Установка

Python 3.10+:

```bash
python -m pip install -r requirements.txt
```

Запускай команды из корня проекта.

## Структура

```text
jobs/
  layout.json                 # единый размер tiles и перекрытие
  center/
    region.png                # стартовый tile в точке (0, 0)
  west_01/
    input/                    # локальные материалы для генерации и склейки
      generation_canvas.png
      generation_mask.png
      prompt.txt
      context_board.png
      source_region_native.png
      neighbors/              # дополнительные соседи, если есть
    generated.png             # результат внешней генерации
    grid_job.json             # параметры подготовки и снимок списка соседей
    tile.png                  # только эта зона с обработанными перекрытиями
    region.json               # координаты, геометрия и зависимости tile
    stitch_meta.json           # сведения о склейке
  west_02/
    ...                       # такой же размер tile, без копии west_01 и center
  _grid/
    world_final.png           # общая карта; пробелы между зонами прозрачные
    grid_preview.png          # уменьшенный просмотр на тёмном фоне
    grid.json                 # список вошедших tiles и позиции в пикселях
```

`input/` и `generated.png` нужны для повторной локальной склейки; для сборки
готового мира нужны `layout.json`, стартовый `center/region.png`, а для каждой
готовой зоны — `tile.png` и `region.json`. Размер данных в одной папке зоны
не растёт с длиной цепочки. Старые результаты в `tmp` не используются.

## Старт и расширение влево

Положи исходную карту в `jobs/center/region.png`.
Её размер задаёт размер всех tiles. При первой подготовке создаётся `layout.json`.
Перекрытие по умолчанию — 256 px (для маленьких изображений не больше трети
меньшей стороны); при первом запуске его можно задать через `--overlap`.
После начала работы геометрия фиксирована.

```bash
python prepare_region_grid.py \
  --jobs jobs --x -1 --y 0 --primary east --job west_01
```

Внешней модели передай:

- `input/generation_canvas.png`;
- `input/generation_mask.png` (белое — генерировать, чёрное — сохранить);
- текст `input/prompt.txt`;
- `input/context_board.png` и дополнительные изображения `input/neighbors/`, если есть.

Реальная полоса перекрытия основного соседа уже находится на холсте и закрыта
чёрной маской. Генерируется только новая территория; фиксированные объекты
нельзя передвигать или перерисовывать. При склейке проверяется средняя пиксельная
ошибка фиксированной области с учётом изменения размера (порог 12 из 255).
Это проверка существенного изменения опоры, а не гарантия совпадения географии.
Если модель меняет опору, склейка останавливается до перезаписи tile.
Задания, подготовленные до появления `fixed_primary_overlap`, нужно подготовить
и сгенерировать заново. Существующие изображения автоматически не исправляются.

Верни изображение точно в размере холста и сохрани как `jobs/west_01/generated.png`.
Скрипт допускает пропорциональное изменение размера и приводит изображение к
единому масштабу сетки; отклонение пропорций более 2% отклоняется.
Например, холст 2372×941 нельзя заменять изображением 1672×941.
Генерацию изображения сами Python-скрипты не выполняют.

```bash
python stitch_region_grid.py \
  --job west_01 --feather 4
```

Результат — `jobs/west_01/tile.png` и метаданные. Общая карта пока не создаётся.

Следующая зона:

```bash
python prepare_region_grid.py \
  --jobs jobs --x -2 --y 0 --primary east --job west_02
# Внешняя генерация → jobs/west_02/generated.png
python stitch_region_grid.py \
  --job jobs/west_02 --feather 4
```

Так же добавляются `west_03` ... `west_500`. Названия произвольные:
расположение определяется координатами, а не номером в имени.
Подготовка не перезаписывает непустую папку задания и не занимает готовую ячейку повторно.

## Общая карта — отдельная команда

```bash
python build_grid_from_jobs.py --jobs jobs
```

Сборщик читает **все** локальные tiles, размещает их с учётом перекрытия
и сохраняет результат только в `jobs/_grid`. Старые `stitched/final_native.png`
игнорируются. `--force` оставлен для совместимости и не требуется.

Для tile размером `W × H` и перекрытия `O` шаг сетки равен
`W − O` по X и `H − O` по Y. Новые tiles накладываются после своих исходных
соседей, поэтому их уже склеенные полосы заменяют исходное перекрытие.
Повторного сглаживания при общей сборке нет.

Большой единый PNG всё равно требует памяти пропорционально площади всей карты.
Дублирования таких PNG в каждой зоне больше нет. Для огромных миров дальнейшим
шагом может быть экспорт частями или пирамида изображений.

## Нижний ряд и другие направления

После создания `west_04`:

```bash
python prepare_region_grid.py \
  --jobs jobs --x -4 --y 1 --primary north --job south_west_04
# Внешняя генерация → jobs/south_west_04/generated.png
python stitch_region_grid.py \
  --job south_west_04
```

Затем сосед справа:

```bash
python prepare_region_grid.py \
  --jobs jobs --x -3 --y 1 --primary west --job south_west_03
# Внешняя генерация → jobs/south_west_03/generated.png
python stitch_region_grid.py \
  --job south_west_03
```

При наличии `west_03` будут учтены северный и западный соседи.
Склейка обрабатывает перекрытия всех соседей, известных при подготовке.
Она уменьшает цветовые швы, но не исправляет несовпадающее русло реки или
дорогу, если модель нарисовала их в другом месте. Общие углы полос обрабатываются
последовательно; глобальной оптимизации стыка четырёх зон пока нет.

Для всех направлений используется `stitch_region_grid.py`.
Источником данных служат `layout.json` и `region.json`; отдельный реестр состояний не нужен.

## Если модель изменила закреплённую область

Ошибка `Generator changed the fixed anchor` означает большую пиксельную разницу,
а не доказательство плохого стыка. Маска, приложенная картинкой в чат, сама по себе
не гарантирует технического ограничения области редактирования.

Для просмотра без публикации:

```bash
python stitch_region_grid.py --job west_01 --draft
```

Результаты пишутся только в `jobs/west_01/draft/`: `tile.png`, отчёт и
`primary_pair_preview.png` (пара с основным соседом). Общая карта и основной tile
не меняются; сборщик не включает черновики. При изменённой опоре черновик использует
поиск шва, но не подменяет весь overlap жёсткой полосой исходного изображения.
Согласованность рек, дорог и рельефа нужно оценить визуально.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Проверки выполняются на синтетических изображениях во временных папках:
цепочка зон, все направления, второй нижний ряд, несколько соседей,
масштаб, повторная сборка и отсутствие накопленных панорам в папках зон.
Старые `region.json` без формата `local_tile_v1` намеренно отклоняются:
их геометрию нужно мигрировать отдельно, чтобы не разместить зоны неверно.
